# Python 代码审查与修复

输入：一个文件或目录路径。输出：外科手术式修复后的代码 + 改动清单。

## 铁律

- **不改变运行时行为**。只动写法、规范、命名、注释。任何可能影响行为的改动，先提出、标为「需确认」，不擅自改。
- **外科手术**：每行改动可追溯到本次需求；不重构无关代码，不删既有死代码（只提出）。
- **先基线后修复**：改前跑测试，改后再跑；拿不到证据就说「未验证」。
- 无法判定 / 越界的项，列进「未改·需确认」，别猜。

## 工作流

```
Task Progress:
- [ ] 1. 定范围：解析输入，列出目标 *.py（跳过 .venv / 生成物 / 迁移脚本等）
- [ ] 2. 记基线：pytest 绿？lint 现状？
- [ ] 3. 扫描四类问题：语法 / 规范 / 命名 / 注释
- [ ] 4. 逐项修复（行为不变）
- [ ] 5. 验证：pytest 仍绿 + lint 通过 + diff 只含预期改动
- [ ] 6. 汇报：改动清单 + 未改项
```

**第 1 步 · 定范围**：目录则递归收集 `.py`，排除 `__pycache__`、`.venv`、构建产物；与用户确认是否含 `tests/`。

**第 2 步 · 基线**：仓库根执行 `uv run --no-project pytest <path>`；有 ruff 就跑 `uv run ruff check <path>`、`uv run ruff format --check <path>`。测试红就先报告，别在红基础上动手。

**第 5 步 · 验证**：pytest 必须与基线一致（不新增失败）；lint 数（错误项）应下降或持平；`git diff` 逐块确认无行为改动。工具缺失时以人工核对替代，并注明。

## 四类检查项

### 1. 基本语法 / 现代写法
- 手写 for 累积 → 列表/集合/字典推导式、`sum()`、`any()`、`all()`
- `range(len(x))` 取索引 → `enumerate` / `zip`
- `%`、`.format()` → f-string
- 裸 `open()` → `with` + `pathlib.Path`
- `type(x) == T` → `isinstance(x, T)`
- `if len(x) > 0:` / `== None` → `if x:` / `is None`
- 循环内字符串 `+=` → `"".join(...)`
- 可变默认参数 `def f(x=[])` → `None` + 函数体内初始化
- `except:` / `except Exception: pass` → 具体异常 + 日志

### 2. 代码规范 / 格式
- 未使用的 import / 变量 / 函数 → 删除**本次改动产生的**孤儿；既有的只报告
- import 分组排序（标准库 / 第三方 / 本地）
- 空白、缩进、行长交 formatter，不手改
- 公开函数 / 类补类型注解；禁止用 `Any` 兜底（见 `60-python-conventions`）
- 库代码里 `print` → `logging`（CLI 输出走专用 renderer）

### 3. 命名规范
- 模块 / 函数 / 变量 `snake_case`，类 `PascalCase`，常量 `UPPER_SNAKE`
- 布尔用 `is_` / `has_` / `can_` 前缀
- 禁用内置名当标识符：`list`、`dict`、`id`、`type`、`input`…
- 弃单字母（循环 `i`/`j`、坐标 `x`/`y` 除外）、拼音、无意义缩写
- 重命名先查引用范围；跨文件/跨模块的大范围改名先征求确认

### 4. 注释合理化
- 删掉复述代码的注释（`i += 1  # i 加一`）
- 修正过时 / 误导的注释（比错误代码更危险）
- 注释讲「为什么」，不讲「是什么」；不重复类型注解已表达的信息
- 公开函数 / 类补 docstring（用途、参数、返回、异常）；简单私有函数不强制

## 严重度分级（用于汇报）

| 级别 | 含义 | 处理 |
|------|------|------|
| 🔴 错误 | 会改变或掩盖行为的写法（可变默认参数、裸 except） | 直接修 |
| 🟡 规范 | 违反约定、命名/格式问题 | 直接修 |
| 🟢 优化 | 现代写法、注释精简 | 直接修，可回退 |
| ⚪ 需确认 | 涉及行为、跨模块、或语义不明 | 只提出，等确认 |

## 汇报模板

```markdown
## 修复清单（<path>）

### 🔴/🟡/🟢 <文件>:<行>
- 前：<原写法>
- 后：<新写法>
- 因：<对应检查项>

## 未改·需确认
- <文件>:<行> <问题> —— <为何不确定>

## 验证
- pytest：<命令> → <结果，是否与基线一致>
- lint：<命令> → <前后对比>
```

## 不做

- 不改逻辑、不改接口签名语义、不动测试断言
- 不引入新依赖、不改 `requirements.txt` / `pyproject.toml`
- 不做跨模块大规模重构（拆分模块等按需单独任务）
- 不清理非本次改动产生的死代码
